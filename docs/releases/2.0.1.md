# Track 2.0.1 — Security hardening

Release 2.0.1 of the Track 2.0 roadmap (SEC-001 to SEC-004). Baseline: `856c4d7`
(tagged `v1.0-baseline` locally; see *Known limitations*). Branch:
`feature/2.0.1-security-hardening`.

## Release notes (for you, the user)

- **AI is off until you say yes.** The Coach tab now asks first and shows exactly what
  would be sent and to whom. Private stamina data needs its own yes. You can turn
  either off at any time in **Settings → Privacy & AI consent**, and nothing more is sent.
- **Autopilot is off by default.** If you want the AI to move reminder times by itself,
  tick it when you agree to AI coaching, or switch it on later in the Coach card.
- **The AI coach and reminders are locked on the server until protected.** Set
  `PUSH_ACCESS_CODE` (12+ characters) in Vercel, redeploy, and type the same code in
  **Settings → Notifications → Access code**.
- **Encrypted backups.** Settings → Your data → *Encrypted backup* saves a
  password-protected file. Plain backups no longer include this device's notification
  setup or access code.
- A clear warning that your logs live only in this browser, with the date of your last backup.

Nothing you've logged is deleted or changed. Saves from before this release keep all
their records; only the old "share private data by default" setting is dropped.

## Security checklist

- [x] No external AI transmission without current coaching consent (client and server).
- [x] Private wellness data needs separate consent; revoking excludes it immediately.
- [x] Autopilot off for new users; off when coaching consent is revoked.
- [x] No publicly callable paid endpoint: deployments fail closed without a strong access code.
- [x] Push schedules can't be modified or deleted without holding the device's subscription.
- [x] QStash delivery still requires a valid signature (existing tests pass).
- [x] Request size, structure and values validated; API keys only in server env vars.
- [x] Backups carry no access code or push wiring; encrypted option available.
- [x] No health data or provider error text in server logs.
- [x] CSP and browser security headers; 0 known dependency vulnerabilities; CI added.
- [ ] Durable (cross-instance) rate limiting and spend limits: needs the phase 1 database.
- [ ] Server-verified identity and consent records: phase 1 accounts.

## Known limitations

- **Rate limits and the daily AI ceiling are per server instance** (in memory). The hard
  ceiling on AI spend is the limit set on the OpenRouter key ($50). Durable limits come
  with the phase 1 database.
- **Consent is recorded on the device.** The server enforces the consent the app claims
  and strips private fields without it, but can't verify the claim until accounts exist.
- **The shared access code is not user authentication.** It stops strangers, not someone
  who has the code. Phase 1 replaces it with accounts.
- **The baseline tag could not be pushed** from this environment (the git proxy refuses
  tag refs). Create it in GitHub → Releases → *Draft a new release* → tag `v1.0-baseline`
  on commit `856c4d7`, or run `git push origin v1.0-baseline` from your machine.

## Deploying to production

1. In Vercel → Settings → Environment Variables, add `PUSH_ACCESS_CODE` (12+ characters,
   Production). Until this is set, the AI coach and reminders are locked after deploy.
2. Merge the pull request, then deploy production (`vercel deploy --prod`, or ask Claude).
3. On your phone: open the app, enter the code in Settings → Notifications → Access code,
   then answer the AI consent prompt on the Coach tab.

## Rollback

- **Code:** redeploy the previous production deployment in Vercel → Deployments →
  (the deployment before 2.0.1) → *Promote to Production*, or deploy commit `856c4d7`.
  No data migration runs on the server, so nothing needs undoing there.
- **Device data is safe either way.** 2.0.1 only adds fields (`consents`, `consentLog`,
  `lastBackupAt`, push ownership) and removes the unused `aiPrivate` flag. 1.0 ignores
  the new fields. **Privacy caveat:** 1.0 fills the missing `aiPrivate` flag with its old
  default, which is *on*. After a rollback, untick *Include private stamina data* on the
  Coach tab, and switch the autopilot off if you don't want it.
- **Push:** schedules created by 2.0.1 use owner-hashed IDs. If you roll back after push
  was set up, turn notifications off and on once so 1.0 recreates its own schedules.
